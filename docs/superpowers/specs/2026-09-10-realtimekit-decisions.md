# Approved design decisions — RealtimeKit live rooms (Nelson approved 2026-09-10)

## 1 · Shape
Two room kinds, one engine. OPIL Thread = CLASS: one RealtimeKit meeting per ea_opil_sessions row (kind='thread'), everyone on camera, mute-all, breakout rooms, screen share. Academy /live/ = WEBINAR: one meeting per ea_live row, Nelson on stage, members watch with chat, polls, raise-hand (request stage), can be brought up. Judges sit in OPIL meetings on a no-media preset (mixed presets in one meeting is documented).
Today's Cloudflare Stream path stays as BROADCAST MODE on the same pages (OBS/RTMPS, phone app, the /assets/live-demo loop, and the existing WHIP camera button) for one-way nights. ROOM MODE is RealtimeKit. The host picks; students never see the difference.

## 2 · Who gets what (five presets, decided server-side from existing RPCs)
- Academy: ea_is_admin() → tma-webinar-host (stage, recording, mute-all, kick, accept stage requests); ea_is_member() → tma-webinar-member (watch, chat, polls, raise hand → stage: audio/video/screenshare/stage_access ALL = CAN_REQUEST per Cloudflare's webinar recipe); else 403 → existing upsell state.
- OPIL: ea_opil_my_role() returns jsonb {admin, judge, facilitator_sessions:int[]}. admin || facilitator_sessions.includes(session_no) → opil-host (+ breakout room management); judge → opil-judge (view + chat, no media); ea_opil_in_cohort() (membership in ea_opil_team_members — NOT registrations.approved) → opil-student (camera, mic, screen share, chat, polls, breakouts); else 403.
- No Cloudflare secret in any page. One edge function (ea-rtk-join) hands out a per-person participant token; same auth pattern as ea-live-publish (verify_jwt OFF, Bearer user token → service-role auth.getUser → RPCs as the caller; CORS locked to https://taylormadeacademy.com).

## 3 · Recording, replay, captions
- Host taps Start → recording started server-side via the Start Recording API (explicit; do NOT rely on record_on_start, which requires dashboard storage config and whose docs contradict themselves). realtimekit_bucket_config enabled (RealtimeKit's own bucket, 7-day presigned downloadUrl). No R2.
- Webhook recording.statusUpdate status=UPLOADED → call Cloudflare Stream POST /accounts/{id}/stream/copy {url: downloadUrl, meta:{name}} with the EXISTING Stream:Edit token (secret CF_API_TOKEN, account CF_ACCOUNT_ID) → Stream video uid → watch URL https://customer-nimm2h959enrq4x1.cloudflarestream.com/<uid>/watch → written to ea_live.replay_url / ea_opil_sessions.recording_url (the exact fields today's broadcast.js writes).
- End for everyone = kick-all AND an explicit PUT /recordings/{id} {action:"stop"} (kick-all is not documented to stop recordings).
- Transcript + AI summary after each meeting (transcribe_on_end, summarize_on_end, summary_type lecture, Whisper — pennies). Summary → a DRAFT "playbook" the coordinator/admin sees on the session via a service-role table + admin-only RPC. NEVER on ea_opil_sessions/ea_live rows (those rows are readable by every student/member via sess_read / ea_live_member_read and both pages select('*')).
- Live captions default to hosts only (Nova-3 real-time ≈ $0.0092/min per captioned participant ≈ $0.55/hr per person; 27 students would triple session cost).

## 4 · Data and plumbing
- Migration: rtk_meeting_id text AND mode text not null default 'stream' check (mode in ('stream','meeting')) on ea_live and ea_opil_sessions (mode is the page's branch key — the meeting id persists across days so it cannot stand in for 'is this row in room mode'), both locked from client updates (column-level REVOKE UPDATE (rtk_meeting_id) ON ea_opil_sessions FROM authenticated, or a trigger) because sess_fac_update lets a facilitator update any column of their own sessions. Service role is the only writer.
- Three service-role-only tables: ea_rtk_participants (meeting_id, user_id, participant_id, preset_name), ea_rtk_events (id = rtk-uuid header, event, meeting_id, payload jsonb with streamKey redacted, received_at) for dedupe + audit, ea_rtk_artifacts (meeting_id, room, ref, kind recording|transcript|summary, url, expires_at, text, status). Admin/coordinator RPC ea_rtk_session_notes(room, ref) → summary/transcript text for the host UI.
- Three edge functions, all verify_jwt OFF + own auth like ea-live-publish:
  - ea-rtk-join: body {room:'academy', live_id} | {room:'opil', session_no} → role → create-or-get meeting (title, persist_chat, transcribe_on_end, summarize_on_end, ai_config) with a race-safe UPDATE … WHERE rtk_meeting_id IS NULL and orphan retire (PATCH status INACTIVE) → add participant (custom_participant_id = Supabase auth user id, never email; name from ea_profiles.display_name; preset by role) or refresh token for an existing participant (POST participants/{id}/token) → {token, meeting_id, preset}.
  - ea-rtk-host (host roles only): start_recording / stop_recording / end_session (kick-all + explicit stop) / status; flips is_live on the row and, when going live, first clears is_live on OTHER rows (partial unique indexes ea_live_one_live / ea_opil_sessions_one_live) — never trips 23505; never reloads a page.
  - ea-rtk-webhook: verify rtk-signature (RSA-SHA256, public key from https://api.realtime.cloudflare.com/.well-known/webhooks.json), dedupe on rtk-uuid, handle meeting.started/ended (ended → is_live=false), recording.statusUpdate (UPLOADED → Stream copy → replay), meeting.transcript / meeting.summary (fetch text within the 7-day window and store in ea_rtk_artifacts), livestreaming.statusUpdate (status vocab LIVE|OFFLINE|IDLE differs from the REST enum LIVE|IDLE|ERRORED|INVOKED — separate handling). Do inline work; EdgeRuntime.waitUntil only after a staging check.
- One-time setup in Cloudflare (Chrome): create the RealtimeKit app (dashboard, so default presets exist), create a Realtime Admin API token (scoped, roll+zoom+verify routine, secret CF_RTK_API_TOKEN + CF_RTK_APP_ID), create the five presets (API or dashboard), register the webhook (probe GET /webhooks vs /webhooks/all — the docs disagree).

## 5 · The room on the page
- The center of both pages becomes the RealtimeKit meeting in Academy colors/type (navy #04123a/#0a1733, gold #fdc921, Space Grotesk/Inter via design tokens), filling the space (its own #rtk-root layout, not the 16:9 .player box); on OPIL phones the bottom .ln-dock hides while in a meeting (body class), since nav() appends a fixed dock.
- Load from CDN the way hls.js already loads: core via https://cdn.jsdelivr.net/npm/@cloudflare/realtimekit@2.0.2/+esm (the plain dist/index.es.js has bare specifiers and dies in a browser) — or the IIFE dist/browser.js; UI kit via https://cdn.jsdelivr.net/npm/@cloudflare/realtimekit-ui@2.0.2/dist/index.js (dist/index.es.js is a 404) plus the loader (loader/index.es2017.js) per the docs' init pattern (RealtimeKitClient.init({authToken, defaults}) then <rtk-meeting> with the meeting prop and its required props: mode, size, gridLayout, config — read the component page for exact values). Pin exact versions; add the new same-origin js/css to build_site.py's _asset_ver + _ASSET_RX and bump sw VERSION.
- Chat inside the meeting (files, emoji) while a meeting runs; the existing ea_live_chat / ea_opil_live_chat stays for broadcast mode.
- Host controls in room mode call ea-rtk-host and update the DOM in place — no location.reload() (the existing Go live / End handlers reload and would tear the meeting down). Hand-raise queue is built from the stage events (stageAccessRequestUpdate / newStageRequest), not a getter.
- Broadcast control keeps its existing paste-URL / demo / WHIP camera paths under "Broadcast (one-way)"; a new "Start class" / "Start webinar" button is room mode.

## 6 · Cost and spikes
- Verified rates 2026-09-10: A/V participant $0.002/min; audio-only $0.0005/min; export (recording or RTMP/HLS out) $0.010/min; raw RTP to R2 $0.0005/min; captions Nova-3 $0.0092/min per captioned participant; Whisper $0.0005/min (Workers AI, 10k Neurons/day included). OPIL session 27 × 60 min recorded ≈ $3.84; Academy webinar 50 ≈ $6.72; 200 watching ≈ $24.60/hr.
- Spikes before build: (1) load the kit from jsdelivr + init with a real token in a harness against a staging app; (2) participant token lifetime is undocumented — refresh on every join; (3) rtmp_out_config into the existing Stream input (overflow / HLS) is a documented field but untested — phase 2 behind a switch; (4) judge no-media GROUP_CALL preset rendering inside the class; (5) meeting size cap undocumented (grid pages at 100).

## Amendments after spike 1 (2026-09-10, same day)
- CORE LOADS AS THE IIFE: `<script src="https://cdn.jsdelivr.net/npm/@cloudflare/realtimekit@2.0.2/dist/browser.js">` → `window.RealtimeKitClient`. The `/+esm` route is DEAD in practice: jsdelivr's ESM conversion of the dependency `sdp-transform@2.15.0/+esm` returns 404 and the whole graph aborts (verified in Playwright). UI kit stays ESM: `loader/index.es2017.js` → `defineCustomElements()`, and `dist/index.js` (provideRtkDesignSystem, BreakoutRoomsManager, RtkUiBuilder, defaultConfig, defaultIconPack, extendConfig, registerAddons…).
- With `showSetupScreen = false`, assigning `.meeting` makes `<rtk-meeting>` join by itself; calling `meeting.join()` as well throws `UnsupportedConcurrentMethodExecution`. Never call join manually in that mode.
- `rtkStatesUpdate` detail is `{meeting: 'idle'|'joined'|…, prefs:{mirrorVideo, muteNotificationSounds}, peerId…}`; `meeting.self.roomJoined`, `meeting.self.presetName`, `meeting.participants.joined` (Map), `meeting.self.permissions.{canProduceVideo|canProduceAudio|canProduceScreenshare ('ALLOWED'|…), chatPublic.canSend, polls.canCreate, connectedMeetings}` all verified live.
- Default presets `group_call_host` and `group_call_participant` both grant video/audio/screenshare ALLOWED + chat + polls-create — our custom presets must tighten (students: no polls-create; judges: no media).
- Product defaults settled by the spec repair (routine, not re-asked): ONE room-mode button ("Start class" / "Start webinar") that mounts the room and, once joined, starts the recording — no separate "Open room" step; ea-rtk-host gains `start` to carry it; `can_livestream` is false on every v1 preset; chat files on for members and students, judges text-only; `ea_live.access='public'` rows are broadcast-only in v1 (room mode is members-only) — ticket holders/public rooms are a §17 question; breakout (connected) meetings are audit-only in v1 (not recorded/transcribed); playbook artifacts key on (room, ref) when the webhook carries no session id.
- Implementation details settled during spec critique (not new product decisions): artifact rows (transcript/summary/playbook) are UPSERTs so webhook retries are safe; `rtk_session_id` and `rtk_started_at` join `rtk_meeting_id`/`mode` as server-written, trigger-locked columns so a delayed `meeting.ended` (Cloudflare keeps an empty session alive ≤120 s) can never flip a restarted room off air; `<rtk-meeting>` props beyond `meeting`/`showSetupScreen` are set only after spike 1(c) (the API reference); the local Supabase staging stack is itself a pre-build spike (19) — if the migrations don't replay cleanly locally, staging becomes a second hosted project.
